# Decisions and Open Questions

Copied from the claude.ai Project on 2026-10-25. Append decisions as they are made, with date and one line of reasoning. Do not delete superseded decisions; mark them superseded.

## Decisions

- 2026-10-25: Project name is **Heliostat**.
- 2026-10-25: Build on Solaar's rules engine and `rules.yaml` format; do not reimplement HID++.
- 2026-10-25: Delivery vehicle is **standalone app plus a small upstream reload PR**. Standalone gives UX freedom; the reload PR is tiny because Solaar already forwards remote commands to its running instance; Debian 13 ships Solaar 1.1.14, so a restart-based fallback is needed for years regardless.
- 2026-10-25: Rule reload strategy: use the upstream remote command when the installed Solaar supports it (version-gated), otherwise restart Solaar after save. Never rely on the user pressing reload in Solaar's own editor.
- 2026-10-25: License is **GPL-2.0-or-later**. Compatible with Solaar's v2-only and v2-or-later files, permits importing or adapting Solaar code, and matches the license upstream contributions will carry.
- 2026-10-25: **Rules model:** Heliostat owns a typed model of `rules.yaml` and does not import Solaar at runtime. Conformance tests run pinned Solaar 1.1.14 and latest in subprocesses and require Heliostat's output to be byte-identical to Solaar's own save (conformance rule refined 2026-10-26, see "Save target revised"). Decouples Heliostat from Solaar's private APIs across the 1.1.14 to 1.1.20+ span.
- 2026-10-25: **Toolkit:** Qt 6 via PySide6, Qt Widgets (not QML). Native on the KDE dev desktop, mature testing via pytest-qt.
- 2026-10-25: **Device data in v1:** parse `solaar show` / `solaar config` CLI output, with per-version captured fixtures. Live button capture deferred past v1.
- 2026-10-25: **Packaging for v1:** pip-installable pyproject project (pipx/venv). Debian package later; Flatpak deferred (sandbox conflicts with the host `solaar` CLI and `~/.config/solaar`).
- 2026-10-25: **v1 scope:** lossless editing of all rules (simple editor plus advanced tree), diversion awareness with one-click divert, lint/conflict detection, safe save with backups and external-change detection, Apply with reload, `heliostat lint` CLI. Deferred: live capture, dry run, presets, comment preservation.
- 2026-10-25: ~~**Save target:** byte-identical to Solaar's own save, not merely loadable by Solaar.~~ Superseded 2026-10-26 (see below).
- 2026-10-25: **Names:** PyPI distribution `heliostat`, repo `rtk94/heliostat`, app ID `io.github.rtk94.Heliostat`. Name check found no conflicts in the Linux desktop / Logitech space.
- 2026-10-25: **Phase 0** (repo bootstrap) done directly from the planning chat rather than via a Claude Code prompt. ~~Phase prompts live in `prompts/`.~~ Superseded 2026-10-27 (see "Phase prompts" below).
- 2026-10-26: **Save target revised** (supersedes 2026-10-25 "byte-identical to Solaar's own save"). Required: every supported Solaar version loads Heliostat's output as the rules Heliostat holds. Formatting matches Solaar's save byte-for-byte except documented deviations. Deviation D1: Feature arguments are written as loaded; new Feature conditions use underscores, because Solaar 1.1.14 cannot load the spaced form its own save writes (fixed in 1.1.15). Existing misloadable forms are preserved and flagged by lint, never silently rewritten. Found in Phase 1a: on 1.1.14, two saves from Solaar's own editor turn `THUMB_WHEEL` into `None`.
- 2026-10-26: **Broken YAML:** if rules.yaml fails to parse anywhere, Heliostat refuses to edit or save it, reports the error location, and warns that Solaar is running only the rules before the error and will drop the rest on its next save. Found in Phase 1a: Solaar keeps the rules before a YAML error and silently drops the rest.
- 2026-10-26: **Lint additions:** HL000 parse error, HL007 spaced Feature name (error on Solaar < 1.1.15, warning otherwise), HL008 `Feature: None` (feature already lost).
- 2026-10-26: **First upstream contribution** is a one-line docs fix: the published rules example (docs/rules.md) is missing a `---` before `- Feature: CROWN`, so PyYAML stops after 3 of 6 rules. Do this before opening the reload-rules issue. No Debian bug report for the 1.1.14 Feature bug for now.
- 2026-10-26: **Deviation D2 (argument shapes):** every component argument is written in the shape it was loaded (shorthand such as `KeyPress: X`, scalar vs one-item list, invalid or out-of-range values), never rewritten to Solaar's canonical shape or fallback. Components Heliostat creates use Solaar's canonical shapes, so files Solaar saved and rules Heliostat builds still match Solaar's save byte-for-byte (modulo D1). Reason: Solaar's save rewrites shapes, replaces invalid arguments with fallbacks that can delete actions, and collapses one-item lists in ways that change meaning or produce files it cannot reload. Preserving keeps edits minimal and never changes what Solaar does.
- 2026-10-26: **Formatting tests restructured:** byte-for-byte comparison (modulo D1) only against Solaar-canonical input: Solaar's own re-save of a fixture, and rules Heliostat builds. As-written fixtures are covered by semantic equality on both versions plus idempotence (dumps of load of dumps output is unchanged). On 1.1.14, D1 accepts Heliostat's preserved spaced Feature name where Solaar's save wrote None; the semantic test proves both load as None there.
- 2026-10-26: **Valid YAML that aborts Solaar's load** (e.g. `Feature: [CROWN]`, `Rule: 5`, a null document, `Test: mouse-up`) stays editable in Heliostat; lint HL009 reports it as an error: Solaar stops loading at that rule, and its next save drops everything after it.
- 2026-10-26: **Lint HL010 solaar-save-hazard** (warning): a rule contains a form Solaar's own save would damage: a one-item-list collapse that changes meaning or makes the file unloadable, an invalid argument Solaar replaces with a data-deleting fallback, or an unknown component that makes Solaar's save fail.
- 2026-10-26: **Diversion mode readback (Phase 2):** Solaar's CLI reads `divert-keys` from the device's divert bit alone, so Mouse Gestures and Sliding DPI read back as Diverted. `controls()` reports a live Diverted on a control that offers gesture modes as `diverted (gesture mode unknown)`, never a guess. The mode Solaar has stored in its config.yaml (the "(saved)" line of `solaar show`) is reported separately as `saved_mode`.
- 2026-10-26: **Restart procedure (Phase 2):** find the user's single Solaar GUI process in /proc. If its cgroup leaf is a systemd user `.service` whose MainPID is that process, run `systemctl --user restart <unit>`. If the process is not in a user service, SIGTERM it, wait up to 10 s, then relaunch it with the same argv, cwd and environment, detached. Never SIGKILL; never restart a unit whose main process is something else. Verified on the dev machine 2026-10-26: `heliostat debug-reload` restarted via systemd, `app-solaar@autostart.service`, pid 14327 -> 1314044 with the same argv (`/usr/bin/python3 /usr/bin/solaar --window=hide`), and both devices came back online.
- 2026-10-26: **CLI conventions (Phase 2):** `solaar` runs with `LANGUAGE=C LC_ALL=C.UTF-8` (setting labels and mode names are translated). Devices are read from `solaar show` (all) and the online pairing is picked by serial, because `solaar show <serial>` prints the first pairing with that serial, which can be a stale offline one. `solaar config` is addressed by serial (it skips offline pairings).
- 2026-10-26: **HL001 mode check uses saved_mode:** the "(saved)" line of `solaar show` names the exact mode Solaar holds in config.yaml (captured in `tests/fixtures/solaar/1.1.14/show_all_back-gestures.txt`: saved Mouse Gestures, live Diverted). HL001 can check that a MouseGesture rule's control has `saved_mode` Mouse Gestures, provided the live mode is diverted (live Regular means the device is not diverted, whatever was saved).
- 2026-10-26: **Attribution:** rtk94 is the only author and contributor anywhere: commits, PRs, and files, for Heliostat and upstream Solaar contributions. No AI co-author trailers or "Generated with" lines.
- 2026-10-26: **Solaar name tables (Phase 3):** lint needs Solaar's control, feature, Test and gesture names per version without importing Solaar, so `tools/gen_solaar_names.py` reads them (statically, with `ast`) from the pinned checkouts into `src/heliostat/solaar/names.py`; a unit test fails if the file is stale. The source files are GPL-2.0-or-later. Versions up to 1.1.14 use the 1.1.14 tables, 1.1.15 and later the 1.1.20 tables; findings that depend on names are warnings for any version other than the two pinned ones.
- 2026-10-26: **Lint severities (Phase 3):** errors are things that certainly do not work on the installed Solaar (HL000, HL001, HL002 unknown name, HL006, HL007 on < 1.1.15, HL008, HL009). Warnings: likely mistakes or hazards (HL002 control no connected device has, HL003, HL004, HL005, HL007 on 1.1.15+, HL010, and HL009 when only another supported version aborts). Notes say which checks could not run. HL006 is an error because the None result stops every later rule, not just its own.
- 2026-10-26: **HL004 is conservative:** it only uses earlier rules whose leading conditions depend on the notification alone (Modifiers too, when no action sits between the two rules), and that end in actions and sub-rules only. What it does not cover is listed in docs/lint.md.
- 2026-10-26: **HL010 scope:** reports meaning-changing collapses, content-deleting fallbacks (Later contents, Set/Setting arguments, Key/KeyIsDown/Feature names), the 1.1.14 underscore Feature save, and forms Solaar's save cannot write at all. It does not report invalid words in fixed vocabularies that Solaar already ignores (Test names, MouseClick buttons, modifiers, Key actions, Report, MouseScroll): those rules work the same after Solaar's save. Every case, positive and negative, is a conformance test.
- 2026-10-26: **HL006 session detection:** Solaar tests `WAYLAND_DISPLAY` in its own environment; lint treats `XDG_SESSION_TYPE=wayland` or `WAYLAND_DISPLAY` in Heliostat's environment as Wayland, and `GNOME` in `XDG_CURRENT_DESKTOP` as GNOME. Solaar's GNOME extension is not checked.
- 2026-10-26: **`heliostat lint` options:** `--no-solaar` (skip device checks), `--solaar-show FILE` (device data from saved `solaar show` output, through FakeSolaar), `--solaar-version X.Y.Z`. They make lint usable without devices and reproducible from captured output in bug reports.
- 2026-10-26: Code or data copied from Solaar keeps Solaar's copyright notices; Heliostat's own authorship is rtk94 only.
- 2026-10-26: **Simple rule shape (Phase 4):** a trigger, at most one each of Device, Modifiers and Process, then one or more of KeyPress, MouseClick, MouseScroll, Execute, Set. Conditions may come in any order but all come before the actions. `Modifiers: []` is kept as "no modifier held" (Solaar compares the modifier state for equality), distinct from no Modifiers condition. A MouseGesture trigger needs at least one item. Later, Test, Feature, Not/Or/And, MouseProcess, nested rules and any Raw component send a rule to the advanced editor.
- 2026-10-26: **Simple-rule triggers:** pressed, released, or a mouse gesture. No "any" trigger: Solaar has none, and an Or of pressed and released fires the action twice per click. Such rules stay in the advanced editor.
- 2026-10-26: **Simple rules keep their written form (Phase 4):** a recognized rule remembers each condition component as loaded and the condition order, and generate() writes an unedited condition back unchanged; actions are the model's own components, which keep their shapes (D2). An edited condition is written in Solaar's saved shape, and a condition added later goes after the existing ones. Order is kept for meaning as well as bytes: a Process condition before the trigger runs on every notification, and on Wayland outside GNOME its None result stops all later rules (HL006). Property tests check that every recognized rule regenerates byte-identically; a conformance test checks that new simple rules load in both pinned versions as held and match Solaar's own save.
- 2026-10-26: **GUI shell (Phase 5):** `heliostat` with no command opens the GUI on the default rules path, `--rules FILE` on another file; `--version` replaces the old bare version print. The window opens from the rules file alone and lints it with no device data and the version unknown (every supported version considered), then re-lints when Solaar has answered. Solaar is read on a QThreadPool in steps (version and running, devices, controls) through a client wrapper that asks each question once, and the lint context comes from `LintContext.from_client`, the same as `heliostat lint`. Device names in rule descriptions come from online devices' serials and unit IDs only, compared as loaded, as Solaar's Device condition does.
- 2026-10-26: **`solaar show` once per refresh (Phase 5):** CliSolaarClient keeps the parsed `solaar show` output and shares it between devices() and controls() until `refresh()`, which the GUI calls at the start of each Solaar read; set_divert() and reload_rules() refresh too. A failed `show` is not kept. `refresh()` is part of the SolaarClient protocol. On the dev machine (two online devices) a full read went from three `show` runs and 34.9 s to one run and 11.8 s.
- 2026-10-26: **Safe save (Phase 6):** `rulesfile.save` compares the file on disk with the bytes Heliostat loaded (content, not mtime) and refuses to write if they differ; the GUI then shows a diff (as loaded vs on disk now) and offers reload, overwrite or cancel. Before replacing the file it copies the version on disk to `rules.yaml.heliostat-bak.<UTC timestamp>` (e.g. `20261026T071415.123456Z`), then writes a temp file in the same directory, fsyncs it, renames it over the file and fsyncs the directory; the newest 10 backups are kept, matched by exact name pattern. Saving identical bytes writes nothing and makes no backup. A symlinked rules.yaml stays a symlink (its target is replaced, as Solaar's own `open(path, "w")` does); backups go next to the configured path, in Solaar's config directory. The file keeps its permission bits; a new file gets 0666 minus umask. The check and the rename are not atomic together; an outside write in that instant is lost.
- 2026-10-26: **Undo model (Phase 6):** every edit replaces the whole RuleSet through one QUndoCommand holding the before and after snapshots (rules files are small). Typing into a field merges into one undo step per field, but never into the saved state. An edit that changes nothing in the written output is not recorded.
- 2026-10-26: **Edited components (Phase 6):** an action edited in the simple form is rebuilt in Solaar's saved shape, like an edited condition (Phase 4); untouched actions keep their loaded shapes (D2). The advanced editor edits any component, Raw included, as YAML text in Solaar's style; the text must parse as one YAML value, and a value Heliostat does not recognize is accepted and kept as a Raw, with a note saying so. Feature arguments typed there are kept as typed (lint reports a spaced name); the Add templates use underscores (D1).
- 2026-10-26: **Missing and broken files in the editor (Phase 6):** with no rules file the editor starts empty and Save creates the file (and Solaar's config directory if needed). A file that does not parse, or cannot be read, stays read-only: no editing, Save or Apply.
- 2026-10-26: **Apply (Phase 6):** Save, then `SolaarClient.reload_rules()` on the thread pool; Apply stops if the save is refused or fails. The status bar shows the ReloadResult message, its full text in the tooltip, and a dialog when Solaar did not load the rules. Line numbers (rule list, problems, heading) are shown only while the rules match the file on disk.
- 2026-10-27: **Phase prompts** (supersedes the 2026-10-25 note that they live in `prompts/`): removed from the repo in 539ff1a before the public release, because their outcomes are recorded in this file. A local copy is kept in `prompts/`, git-ignored as local-only AI tooling. Git history (`539ff1a^`) holds the published versions.

## Open questions

### Live device data beyond v1
Long-lived concurrent listening for live button capture is unverified. Solaar's own `solaar config` CLI already does short concurrent HID++ access while the GUI runs.

### Upstream reload PR
Search existing pwr-Solaar/Solaar issues before opening one (not possible during planning). Agree the command shape with the maintainers before coding.

### Restart fallback (resolved 2026-10-26)
On the dev machine KDE runs Solaar as the systemd user unit `app-solaar@autostart.service`, generated from `/etc/xdg/autostart/solaar.desktop`. The restart procedure (see Decisions) was verified with a manual `heliostat debug-reload` run.

### 1.1.20 CLI output (resolved 2026-10-26)
Captured in `tests/fixtures/solaar/1.1.20/` from the pinned checkout. The forms predicted from source (offline devices print only "Device is offline."; key flags as `raw_xy` etc.) were right. One parser change was needed: 1.1.20 prints the IDs of unnamed features byte-swapped (`unknown:1803 {0318}`), so the parser now takes such IDs from the name. Otherwise the same devices, controls, divertable sets and modes parse from both versions, apart from the 1.1.15 control renames.

### Post-v1 candidates
- Lint check: a control in Mouse Gestures mode that is also the trigger of a Key rule fires both rules on one press (see docs/solaar-reference.md, "Evaluation details for lint").
- Second simple shape for wheel and crown rules (Feature + Test triggers, e.g. 'when the thumb wheel scrolls up: ...'): the most common reason rules are not simple in Phase 4's stats (8 of 25).

### Name collisions (resolved, notes kept)
- PyPI: `heliostat` unregistered. Flathub, Debian, AUR: no results.
- GitHub: many unrelated `heliostat` repos (mostly solar hardware); KubedAI/heliostat is a Ray/Kubernetes console. Use "Heliostat for Solaar" in descriptions for searchability.
- Trademarks not checked. Do not register a placeholder on PyPI; publish at first real release.
